# Статическая проверка безопасности API

Проверка исходников текущего handoff; это не результат динамического тестирования, браузерной проверки или теста на проникновение.

## Общие меры

- Изменяющие HTTP-запросы проверяют `Origin` на совпадение с текущим origin и отклоняют `Sec-Fetch-Site: cross-site`. CORS не открыт для сторонних origin.
- Принимаются JSON-тела не более 256 КБ; ошибки разбора JSON возвращают 400, необработанные ошибки API не раскрывают stack trace.
- Устанавливаются `nosniff`, `DENY` для iframe, `no-referrer`, `same-origin` для ресурсов и CSP для ответов API; в production включается HSTS.
- Сессионный токен генерируется криптографически, в БД хранится его HMAC-хэш, cookie — `HttpOnly`, `SameSite=Strict`, `Secure` в production, срок действия — 7 дней. Блокировка аккаунта отзывает его сессии; смена пароля отзывает старые сессии и записывает событие аудита.
- Пароли хранятся как salted scrypt; на входе используется атомарный PostgreSQL upsert счётчика попыток по IP и нормализованному нику. Пароли, временные пароли, cookie-токены и session hashes не записываются в аудит.
- Временный пароль нового пользователя возвращается только при создании аккаунта, в приватном ответе API; API-ответы помечаются `Cache-Control: no-store`.
- При первом запросе `GET /auth/setup-status` в пустой базе автоматически создаётся лидер `Winston_Goodmam` с фиксированным начальным паролем `1234`. До смены пароля доступ к рабочим API закрыт, но любой посетитель публичного сайта может первым забрать этот аккаунт. Владелец должен войти и сменить пароль до передачи ссылки другим; фиксированный пароль не подходит для публичного использования.

## Маршруты и границы доступа

| Группа маршрутов | Доступ и проверка |
| --- | --- |
| `GET /healthz`, `GET /auth/setup-status`, `POST /auth/login` | Публичные по назначению; вход проверяет схему, одинаково отвечает на неизвестный ник/неверный пароль и применяет ограничение попыток. |
| `GET /auth/me`, `POST /auth/logout`, `POST /auth/change-password` | Только действующая серверная сессия. Первый пароль можно сменить до допуска к остальному API. |
| `GET /members` | Сотрудник видит только себя, руководитель — список аккаунтов. |
| `POST /members` | Только руководитель; администратора создавать может только лидер. Пароль не включается в аудит. |
| `PATCH /members/:id` | Только руководитель; назначение роли — только лидер; лидерскую запись нельзя редактировать этим маршрутом, нельзя заблокировать себя. Блокировка отзывает сессии. |
| `GET /events` | Действующая сессия. Создание/изменение/удаление мероприятий — только руководитель. |
| `/standards`, `/standard-assignments`, `/standard-submissions` | Шаблоны и назначения создаёт руководство; сотрудник читает только свои назначения/версии и может сдавать только своё; решение по сдаче — только руководство и с обязательной причиной. |
| `/tasks`, `/task-submissions` | Сотрудник читает только свои задания/версии и может начать/сдать только своё; создание, редактирование, проверка, отмена и удаление задания — только руководство. У задания с историей отправок удаление запрещено. |
| `/discipline` и `/discipline/:id/revoke` | Сотрудник получает только собственную историю; выдача и снятие доступны руководству. Снятие требует причину. HTTP-удаления взыскания нет. Начисление сериализовано `SELECT ... FOR UPDATE` по строке сотрудника, идемпотентный ключ ограничен уникальным индексом; изменение реестра и аудит выполняются в одной транзакции. |
| `GET /audit-logs` | Только руководство, фильтры валидируются, ответ ограничен 200 строками. В интерфейсе нет записи, редактирования или удаления журнала; HTTP-маршруты для этих операций не зарегистрированы. |
| `/storage/uploads/request-url`, `/storage/objects/*path` | Только сессия с актуальным паролем; проверяются формат/размер и сигнатура изображения. Файл читается владельцем или после привязки к назначенному заданию/нормативу/взысканию; руководитель может читать только уже привязанные доказательства. Не прошедшие проверку и непривязанные объекты не выдаются публично. |
| `/notifications` | Только собственные уведомления по `recipientId` текущей сессии. |
| `/dashboard` | Только действующая сессия; данные заданий ограничены ролью и исполнителем на сервере. |

## Журнал и транзакционность

У приложения нет HTTP API или интерфейсной команды для изменения/удаления `faction_audit_logs`; у приложения есть только общий внутренний helper для вставки. События добавляются в той же транзакции, что и соответствующее изменение аккаунта, роли, мероприятия, норматива, задания, сдачи или взыскания. Таблица не использует каскадные FK на пользователя, чтобы сохранить снимок автора/цели.

Это обеспечивает неизменяемость **через интерфейс/API приложения**, но не защищает от владельца PostgreSQL с прямым доступом к таблице. Для защиты и от DBA нужны отдельные SQL-роли и триггер запрета `UPDATE`/`DELETE` — это отдельное изменение инфраструктуры.

## Не выполнено в текущем архивном окружении

- Нет живого проекта Replit и подключённой PostgreSQL для применения схемы и проверки запросов.
- Package proxy ответил `403 Forbidden` при установке зависимостей; поэтому после изменений не подтверждены typecheck и production build.
- Шесть локальных тестов чистых правил дисциплины прошли; нужны последующие интеграционные проверки с PostgreSQL для конкурирующих запросов, идемпотентности, снятия и атомарности аудита.
