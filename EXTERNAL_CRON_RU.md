# Внешний cron-сервис

Защищённая уборка истёкших сессий доступна по адресу:

```text
GET https://<имя-сервиса>.onrender.com/api/cron/maintenance
```

Запрос должен содержать заголовок:

```text
x-cron-secret: <значение CRON_SECRET из Render Environment>
```

Не вставляйте секрет в URL, query string, тело запроса, GitHub или чат. Маршрут `/api/cron/maintenance` только удаляет истёкшие сессии.

## Ежедневное обновление нормативов

Добавьте отдельную задачу по адресу:

```text
GET https://<имя-сервиса>.onrender.com/api/cron/daily-standards
```

В заголовке `x-cron-secret` укажите `CRON_SECRET` из Render Environment. Расписание — каждый день в **23:59, часовой пояс Europe/Moscow**. Повторный вызов в тот же московский день не создаст дубликаты.

После сохранения лидером ежедневный норматив сразу назначается активным участникам с соответствующим званием. В 23:59 МСК предыдущий автоматический норматив закрывается на проверку; если сотрудник его не сдал, система создаёт запись о пропуске без фиктивных скриншотов. Затем назначается норматив на новый день. Другие звания и ручные назначения не затрагиваются. Если ежедневный режим не включён, новые назначения не создаются.

У новых нормативов ежедневный режим включён по умолчанию. Для уже существующего норматива откройте его редактирование и включите флажок вручную; исторические шаблоны автоматически не активируются.

Для настройки в cron-job.org создайте отдельную задачу для `/api/cron/daily-standards`, выберите «каждый день, 23:59» и часовой пояс **Europe/Moscow**, метод `GET` и заголовок `x-cron-secret` со значением из Render. После сохранения запустите тест и проверьте раздел «Нормативы»: тестовый запрос проводит цикл за текущую дату. Не публикуйте скриншоты с секретом в заголовке.

## Защита и ответы

- Сравнение секрета выполняется с constant-time сравнением; для production нужен `CRON_SECRET` длиной не менее 32 символов.
- IP получает максимум 12 запросов в минуту на каждом процессе.
- PostgreSQL обеспечивает общий лимит: успешная cron-операция допускается не чаще одного раза в минуту для всех инстансов.
- Верный запрос возвращает `200 {"ok":true}`. Неверный секрет скрывается ответом `404`; превышение лимита возвращает `429`; временная ошибка базы — `503`. Секрет не попадает в логи или ответ.

## Пример настройки cron-job.org для уборки сессий

1. Создайте cron job в [cron-job.org](https://cron-job.org/).
2. Укажите HTTPS URL `https://<имя-сервиса>.onrender.com/api/cron/maintenance`.
3. Выберите метод `GET`.
4. В дополнительных HTTP headers добавьте `x-cron-secret` и значение `CRON_SECRET` из Render. Не добавляйте секрет в URL.
5. Вызывайте маршрут только при необходимости уборки просроченных сессий. На Render Free каждый cron-запрос будит сервис и расходует бесплатные часы; не отправляйте частые ping-запросы, чтобы удерживать его включённым.
6. Сохраните задачу, выполните тестовый запуск и проверьте HTTP 200. После настройки не публикуйте скриншот, содержащий значение заголовка.

Внешний cron нужен для расписания нормативов и периодического обслуживания, но не обходит ограничения Render Free: он не гарантирует работу 24/7, может израсходовать месячные бесплатные часы и при превышении квот привести к приостановке сервиса. Ежедневная ротация нормативов требует настроенной задачи; `/api/cron/maintenance` можно вызывать только по необходимости.
