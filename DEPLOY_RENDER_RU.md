# Бесплатный деплой на Render + Supabase

## Схема

- **Render Free Web Service** запускает React/Vite и Express API в одном Node.js-сервисе.
- **Supabase Free** хранит PostgreSQL-данные приложения. Бэкенд подключается к Postgres через Drizzle и `DATABASE_URL`; Supabase SDK и ключи Supabase в браузере не используются.
- **Dropbox** продолжает хранить скриншоты. Для загрузки нужны бесплатный Dropbox-аккаунт и секреты приложения; настройка описана в [DROPBOX_STORAGE_RU.md](DROPBOX_STORAGE_RU.md).

`render.yaml` не создаёт платную базу Render. Миграции запускаются в `startCommand` перед сервером: Render Free не поддерживает Pre-Deploy Command. Поэтому после сна сервис может сначала применить миграции и только затем начать отвечать.

## Настройка Supabase

1. Создайте Supabase-проект на Free Plan. Выберите регион **Frankfurt (Central EU)**, чтобы он совпадал с регионом Render в Blueprint.
2. Откройте **Connect** в Supabase Dashboard и скопируйте URI **Session pooler**. Он работает по IPv4 и подходит для постоянно работающего Node.js-сервиса на Render. Не используйте URI Transaction pooler для этого приложения.
3. Подставьте пароль базы, который задали при создании проекта. Если в пароле есть зарезервированные символы (`&`, `#`, `?`, пробел и другие), URL-кодируйте их.
4. Сохраните URI как `DATABASE_URL` в Render Environment. Не добавляйте его в Git, исходники, чат или фронтенд. Пример формата есть в `.env.example`.

Приложение использует PostgreSQL-драйвер и существующие Drizzle-миграции; отдельное создание таблиц в Supabase SQL Editor не требуется. Миграции применяются командой `pnpm db:migrate` или автоматически при старте сервиса. Миграция включает RLS для всех 17 таблиц приложения; браузерный доступ к ним через Supabase Data API намеренно не настроен, авторизация и роли по-прежнему проверяются на сервере.

## Деплой

1. Загрузите этот проект в GitHub согласно [GITHUB_RU.md](GITHUB_RU.md).
2. В Render выберите **New → Blueprint**, подключите репозиторий и проверьте, что для Web Service выбран план **Free**. Blueprint создаёт только один Web Service — без Render PostgreSQL.
3. При создании Blueprint Render запросит `DATABASE_URL` и Dropbox-переменные со значением `sync: false`. Введите `DATABASE_URL` из Supabase и секреты Dropbox. `SESSION_SECRET` и `CRON_SECRET` создаются автоматически.
4. После первого deploy дождитесь, пока `/ready` ответит `200`. В логах старта миграция должна завершиться до сообщения о запуске API.
5. Подготовьте первую учётную запись лидера по инструкции ниже; бесплатный Render не предоставляет Shell-доступ.

Если настраиваете сервис вручную:

```text
Build Command:
pnpm install --frozen-lockfile --prod=false && pnpm run build

Start Command:
pnpm --filter @workspace/db run migrate && pnpm --filter @workspace/api-server run start

Health Check Path:
/ready
```

Не добавляйте Pre-Deploy Command: он недоступен на бесплатном плане. Render задаёт `PORT`; один Express-сервис обслуживает API и собранный UI на одном origin.

## Первая учётная запись лидера на Free

Отдельная shell-команда не нужна. После деплоя откройте приложение: при первом обращении к пустой базе система автоматически создаст аккаунт `Winston_Goodman` с начальным паролем `1234`. При первом входе лидер будет перенаправлен в настройки и не сможет работать с остальными разделами, пока не задаст новый пароль длиной не менее 10 символов.

Начальный пароль фиксированный. Не передавайте ссылку другим до того, как лидер войдёт и сменит его; после этого дальнейшие входы используют только новый пароль. Не запускайте инициализацию вручную для базы, где уже есть участники.

## Переменные среды Render

| Переменная | Настройка |
|---|---|
| `DATABASE_URL` | Secret: Supabase **Session pooler** URI |
| `SESSION_SECRET` | Blueprint генерирует случайное значение |
| `CRON_SECRET` | Blueprint генерирует отдельное случайное значение |
| `DROPBOX_APP_KEY` | Secret из Dropbox App Console |
| `DROPBOX_APP_SECRET` | Secret из Dropbox App Console |
| `DROPBOX_REFRESH_TOKEN` | Secret Dropbox OAuth |
| `OBJECT_STORAGE_PROVIDER` | `dropbox`, задано Blueprint |
| `DROPBOX_ROOT_PATH` | `/FactionControl/screenshots`, задано Blueprint |
| `NODE_ENV` | `production`, задано Blueprint |

Для production необходимы настоящие Dropbox-переменные, иначе сервер намеренно не стартует. Получить их безопасно можно по шагам из [DROPBOX_STORAGE_RU.md](DROPBOX_STORAGE_RU.md). Не помещайте секреты в `render.yaml`, коммиты или логи.

## Проверка

- `/health` проверяет, что процесс отвечает.
- `/ready` выполняет `SELECT 1` к Supabase PostgreSQL; ожидаемый ответ — HTTP 200.
- Проверьте вход, создание записи и защищённое открытие скриншота. `/ready` не проверяет доступ Dropbox.

## Что означает «бесплатно»

Конфигурация использует тарифы Free, но платформы не гарантируют бесплатную и непрерывную работу без ограничений. Лимиты и правила могут меняться — перед запуском проверьте актуальные страницы [Render Free](https://render.com/docs/free), [тарифов Supabase](https://supabase.com/docs/guides/platform/billing-on-supabase) и [приостановки Supabase-проектов](https://supabase.com/docs/guides/platform/free-project-pausing).

- Render останавливает Free Web Service после примерно 15 минут без запросов; холодный старт обычно занимает около минуты. Диск сервиса временный, Shell и Pre-Deploy Command недоступны.
- Render учитывает месячные бесплатные часы, трафик и минуты сборки. При превышении лимитов сервис может быть приостановлен или новые сборки заблокированы; при подключённом способе оплаты возможны начисления по правилам Render.
- Supabase Free ограничивает объём базы и трафик; проект с низкой активностью запросов может быть автоматически приостановлен после недели. Автоматические резервные копии не входят в Free.
- Render предупреждает, что необычно большой исходящий трафик бесплатного сервиса к внешним базам и API может привести к приостановке.
- Скриншоты остаются в Dropbox и расходуют его отдельную квоту.

Чтобы свести риск списаний к нулю, не подключайте платный тариф и проверьте настройки billing/spend limit в обеих панелях. В таком режиме при исчерпании бесплатных квот приложение может стать недоступно до сброса лимита, а не продолжить работу за плату. Этот архив настраивает бесплатные планы, но не создаёт аккаунты и не может гарантировать нулевую стоимость при любых обстоятельствах.

Структура таблиц и SQL-миграции находятся в `lib/db/migrations`. Для новых таблиц сохраняйте `.enableRLS()` в Drizzle-схеме; для production не используйте `drizzle-kit push`, а применяйте проверенные миграции. Источник текущих данных — Supabase; миграция схемы сама по себе не переносит записи из прежней базы.
